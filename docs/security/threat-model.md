# Threat Model

Status: living document, maintained **before** production-grade storage or
networking is implemented.

Scope: the authorization engine (evaluator, policy and relationship stores,
future control/data planes). The application using the engine is in-scope only
at the integration boundary.

## Threats and mitigations

| #   | Threat                                                                        | Mitigation                                                                                                                                                                                                                               | Status                                                                                                                      |
| --- | ----------------------------------------------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | --------------------------------------------------------------------------------------------------------------------------- |
| 1   | **Policy tampering** (malicious/unauthorized policy change)                   | Immutable versioned artifacts; publication authz (Phase 9 governance); signed artifacts verified by the data plane (Phase 8, ADR-0024)                                                                                                   | Signing + verification **implemented** (Phase 8); publication authz Phase 9                                                 |
| 2   | **Relationship tampering** (forged/granted relationships)                     | Relationship reads served from PostgreSQL in the deployed data plane (Phase 8); writes stay operator/control-plane actions against the authenticated database; a future Relationship API must add authz + idempotency and an audit trail | Read path **implemented** (Phase 8); mutation API designed, unimplemented (Phase 10+)                                       |
| 3   | **Tenant isolation failure** (cross-tenant reads/writes, inheritance leakage) | Tenant-scoped records; edges validated at write time; adversarial security tests from Phase 2; eventual static validation                                                                                                                | Binding invariant, tested from Phase 2                                                                                      |
| 4   | **Stale authorization data** (revocation lag)                                 | Explicit consistency semantics (eventual/bounded/strong); cache keys include state versions; negative caching stricter than positive (`../architecture/caching.md`)                                                                      | **Keying implemented** (Phase 7, ADR-0021/0022/0023 — all three caches); consistency modes designed                         |
| 5   | **Cache poisoning**                                                           | Decisions cached only from verified evaluations; keys include policy+relationship versions; caches never shared across tenants                                                                                                           | **Implemented & tested** (Phase 7, ADR-0021/0022/0023: frozen decisions, artifacts, and rows; error decisions never cached) |
| 6   | **Confused deputy** (engine misused with elevated context)                    | Context is data, validated against policy-declared schemas; subject identity supplied by the caller boundary, documented as caller responsibility; delegation is an explicit relationship                                                | Designed                                                                                                                    |
| 7   | **Privilege escalation** via policy/graph combination                         | Bounded traversal; static analysis goal (`authz validate`); fuzz testing goal (`authz fuzz`, later phases)                                                                                                                               | Deferred (designed)                                                                                                         |
| 8   | **Policy rollback attacks** (reintroducing old permissive versions)           | Versioning is append-only; activation requires explicit deployment action; audit of activations                                                                                                                                          | Designed                                                                                                                    |
| 9   | **Compromised API credentials**                                               | Credential rotation, scoping, least privilege (control-plane concern, Phase 8)                                                                                                                                                           | Deferred                                                                                                                    |
| 10  | **Malicious policy changes** (insider)                                        | Governance workflow: PR → policy tests → review → approval → staged deploy (Phase 9)                                                                                                                                                     | Designed                                                                                                                    |
| 11  | **Explanation information leakage**                                           | Disclosure levels (`none/minimal/standard/debug`); access to higher levels itself authorized (`../design/explanations.md`)                                                                                                               | Designed, tested from Phase 2                                                                                               |
| 12  | **Denial-of-service**                                                         | Request size/batch/traversal bounds; pathological inputs ⇒ explained DENY; rate limiting at service boundary (Phase 8)                                                                                                                   | **Bounds implemented**; body-size cap (413) + opt-in rate limiting (429) at the service boundary (Phase 8)                  |
| 13  | **Malformed policies**                                                        | Validation at publish time, for both structural and text sources (parse/lowering/structural); source capped at 256 KB; loaded artifacts fail closed                                                                                      | Binding invariant; text path implemented & tested (Phase 3)                                                                 |
| 14  | **Cyclic relationship graphs**                                                | Cycle detection terminates paths — no non-termination; cycles ⇒ branch `unknown` ⇒ deny                                                                                                                                                  | **Implemented & tested** (evaluator visited-set)                                                                            |
| 15  | **Pathological evaluation complexity**                                        | Evaluator bounds enforced (`maxTraversalDepth`, `maxVisitedNodes`, `maxBatchSize`); compiled evaluation plans (Phase 3+); benchmarks before performance claims                                                                           | **Bounds implemented & tested**; benchmarks planned                                                                         |
| 16  | **Evaluation error ⇒ silent allow**                                           | Default-deny (ADR-0006): every error path yields DENY or typed infrastructure error; defective artifacts fail closed with `reason: "error"`                                                                                              | **Implemented & tested** (fail-closed suite)                                                                                |
| 17  | **Sensitive data in the engine** (PII)                                        | PII minimization: opaque subject IDs; no names/emails required; observability obeys privacy constraints                                                                                                                                  | Binding principle                                                                                                           |

## Unresolved risks (open questions)

- Exact consistency guarantees and their cost (roadmap consistency-model
  phases) — not yet decided.
- Effective cache invalidation at large graph scale — a research problem
  (roadmap Phase 47), not solved by TTL. Version-keyed global invalidation is
  implemented (Phase 7, ADR-0021) and is always safe; what remains open is
  _scoped_ invalidation, which only affects hit rate, not safety.
- Explanation leakage under adversarial querying at `standard` level — needs
  formal analysis when explanations are implemented.
- Threats from future feature growth (temporal grants, delegation, external
  principals) — each feature must update this document before implementation.

## Process

Every security-relevant feature lands with: updated threat model rows,
security tests, and (if design changed) an ADR.
