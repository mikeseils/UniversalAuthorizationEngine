# ADR-0002: Use pnpm as the package manager

- Status: Accepted
- Date: 2026-09-21

## Context

The project is a pnpm-compatible monorepo with multiple packages. Development is
on Windows/PowerShell. pnpm 10.34.5 is already installed locally.

## Decision

Use **pnpm** (workspace via `pnpm-workspace.yaml`, lockfile via `pnpm-lock.yaml`).

## Reasons

- Strict, content-addressed dependency layout (no phantom dependencies).
- First-class workspace/monorepo support with fast installs.
- Reliable Windows/PowerShell support.
- Lockfile-first workflow suitable for reproducible CI.

## Consequences

- All documentation uses pnpm commands (`pnpm install`, `pnpm test`, ...).
- CI caches the pnpm store.
- npm/yarn scripts are not provided; contributors must install pnpm
  (`corepack enable` or `npm i -g pnpm`).
